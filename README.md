# РЕПКА

Нативная система на Odoo 18 Community для функционального воспроизведения структуры корпоративной ERP без переноса операционных данных на первом этапе.

## Состав

- Odoo `18.0-20251222`, совпадающая с версией исходной системы
- PostgreSQL 16
- восемь OCA-addon wheels с точными версиями и SHA-256
- Caddy для HTTPS в production
- custom addons в `addons/`
- Docker Compose для локальной разработки и VPS

## Требования

- Docker Engine с Docker Compose v2
- OpenSSL
- не менее 4 ГБ RAM для среды разработки

## Локальный запуск

```bash
cp .env.example .env
./scripts/init.sh
```

После инициализации интерфейс доступен по адресу `http://127.0.0.1:8069`. Логин первого пользователя — `admin`; начальный пароль хранится локально в `secrets/odoo_admin_password.txt` и не попадает в Git.

Повторный запуск:

```bash
docker compose -f compose.yaml -f compose.dev.yaml up -d
```

Остановка:

```bash
docker compose -f compose.yaml -f compose.dev.yaml down
```

## Production

1. Указать реальный домен в `.env`.
2. Создать DNS-запись домена на VPS.
3. Запустить базовую и production-конфигурации:

```bash
docker compose -f compose.yaml -f compose.prod.yaml up -d
```

В production наружу публикуются только порты 80 и 443. PostgreSQL и Odoo остаются во внутренних Docker-сетях.

## Резервное копирование

```bash
./scripts/backup.sh
```

Скрипт сохраняет PostgreSQL dump и filestore в локальный каталог `backups/`, исключённый из Git. Оба файла необходимы для полного восстановления.

## Custom addons

Каждый модуль находится в отдельном каталоге `addons/`:

- `repka_suite` — мета-модуль полной установки текущей версии;
- `repka_base` — общие группы и базовая конфигурация;
- `repka_oca` — восемь публичных OCA-модулей в версиях исходной системы;
- `repka_standard` — 98 стандартных модулей, присутствующих в исходной Odoo;
- `repka_fleet_battery` — первый clean-room вертикальный срез: аккумуляторы автопарка.

Следующие отраслевые модули добавляются по подтверждённой карте зависимостей исходной системы.

OCA-зависимости устанавливаются при сборке image из `requirements-oca.txt`. Каждая версия закреплена SHA-256; произвольные транзитивные зависимости отключены. `web_timeline` и `currency_rate_update` распространяются под AGPL-3, остальные подключённые OCA-модули — под LGPL-3.

## Безопасность

- секреты хранятся только в `secrets/` с правами `0600`;
- `.env`, секреты, резервные копии и результаты аудита исключены из Git;
- database manager Odoo отключён;
- образы контейнеров закреплены по версии и digest;
- перед публикацией выполняется отдельная проверка репозитория на секреты.
