# Freight Margin Watch — экономика перевозок (DEMO)

## Что это
Список заказов, где прямые затраты выше выручки либо результат менее 10% выручки.
## Какую проблему решает
Поиск перевозок, требующих финансового разбора, без ручного сравнения нескольких строк.
## Как работает
1. Проверяет идентификаторы, валюту и суммы. 2. Вычитает прямые затраты из выручки с точной десятичной арифметикой. 3. Подсвечивает отрицательный результат или долю ниже 10%. Не складывает разные валюты.
## Какие данные использует
Синтетические суммы в `example_input.json`; потенциальные поля Odoo: `ufs.base.order.freight_amount`, `ufs.forwarder.order.suborder_amount_sum` и `full_profitability`. Их эквивалентность выручке и полной себестоимости НЕ доказана — перед live нужна бухгалтерская валидация.
## Что делает AI
Никакая ML-модель не используется: проверяемые пороги и объяснения.
## Результат
JSON с `review_count`, разницей, долей и причиной для каждого заказа.
## Как запустить
`python3 ai_automations/margin_watch/run.py` (Python 3.9+, только stdlib); альтернативный синтетический файл — `--input /path/to/file.json`; `--mode live` не поддерживается. Тесты: `python3 -m unittest discover -s ai_automations/tests`.
## Пример
Вход DEMO-101: 5000 BYN выручки, 5600 BYN прямых затрат. Обработка: 5000 - 5600 = -600. Выход: `attention=review`, `result=-600.00` (полный `example_output.json`).
## Плюсы
Прозрачно, быстро, проверка валюты.
## Минусы
Не учитывает косвенные расходы, налоги, возвраты и валютные курсы.
## Риски
Не считать результат бухгалтерской прибылью. Неполные затраты вводят в заблуждение.
## Human-in-the-loop
Финансист подтверждает состав затрат и только затем предпринимает действия.
## Техническая архитектура
Локальный `run.py` → `../engine.py` с Decimal → JSON stdout; без записи в ERP.
## Ограничения
DEMO MODE — исполняемая эвристика; LIVE MODE заблокирован до утверждения источника себестоимости, Odoo ACL и валютной политики.
