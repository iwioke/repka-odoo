# Нереализованные идеи — не рабочие сценарии

Все идеи ниже имеют статус BLOCKED для production: технические модели стандартного Odoo могут существовать благодаря зависимостям `repka_suite`, но нет подтверждённых данных, согласованного read-only API/ACL, метрик качества и модели. Ни один пункт не запускается здесь. Для всех: запуск в будущем по расписанию или по событию через согласованный API; автоматизировать можно расчёт/черновик, а изменения заказов, цен, сообщений, платежей и задач — только с подтверждением человека. Экономия времени неизвестна, требуется пилотное измерение. Общая архитектура: ограниченный Odoo API → нормализация и контроль доступа → внутренний движок → версионированный результат → подтверждение в Odoo; запрещён прямой доступ к БД. Минус каждого пункта — затраты на внедрение и контроль качества; плюс — сокращение ручного поиска и единые причины рекомендаций.

Для каждого пункта: проблема/описание; данные и модели; логика и выход; недостающее (почему BLOCKED); риск/ограничение/что изменить. Значения ценности и сложности — гипотезы из каталога, без чисел эффекта.

| Идея | Проблема / требуемые данные и модели | Предлагаемая логика → результат | Почему заблокировано / API и изменение архитектуры | Риск / ограничение |
|---|---|---|---|---|
| Lead scoring / qualification | Приоритет заявок; `crm.lead`, стадии, исходы контактов | Обучение на размеченных исходах → очередь лидов | Нет проверенной истории исходов; read-only CRM API и разметка | Смещение и неравные шансы; проверка менеджером |
| Next best action / follow-up | Ручные напоминания; `crm.lead`, `mail.activity` | Правила/модель времени контакта → черновик действия | Не проверены согласия, ACL и каналы; API чтения активностей, разрешение на создание после проверки | Нежелательные контакты; никогда не отправлять автоматически |
| Lost reason / conversion forecast | Неясные причины потери; `crm.lead`, комментарии | Классификация причин/прогноз → отчёт | Нет размеченных причин и достаточных исходов; CRM API | Низкое качество свободного текста |
| Upsell / cross-sell | Ручной поиск сопутствующих услуг; `ufs.base.order`, `ufs.order.service`, `product.product` | Корзины услуг → рекомендованные услуги | Не проверена полнота номенклатуры/истории; Odoo API услуг | Спам и некорректное предложение |
| Sales / revenue forecast | Трудно планировать объём; `ufs.base.order`, `account.move`, `crm.lead` | Временные ряды → прогноз с интервалом | Нет проверенной истории и соответствия счётов заказам; API + валютная нормализация | Выручка ≠ денежный поток |
| Discount / pricing optimization | Ручной контроль скидок; `sale.order`, `product.pricelist`, `ufs.base.order` | Поиск отклонений → проверка цены | Нет подтверждённой связи скидки с прибылью; API + утверждённые тарифы | Дискриминационная цена |
| Cancellation risk / order anomaly | Позднее обнаружение аномалий; `ufs.base.order`, история стадий | Обучение на отменах → список риска | Не подтверждены события отмены и история; API/аудит изменений | Ложные срабатывания |
| Customer churn / lifetime value | Риск потери постоянных заказчиков; `res.partner`, `ufs.base.order`, `account.move` | Когортный анализ → сегменты | Нет полноты клиентов/оплаты; API с согласованным охватом | Периодические перевозки выглядят как уход |
| Demand / stockout / excess forecast | Неверные остатки; `stock.move`, `stock.quant`, `product.product` | Прогноз потребления → диапазон запаса | Наличие складской деятельности и история не проверены; API остатков/движений | Отрицательные резервы/сезонность |
| Slow-moving / dead stock | Замороженные остатки; `stock.quant`, `stock.move` | Возраст запаса → список для ревизии | Нет подтверждённого складского потока; API + календарь продаж | Редкие запчасти критичны |
| Purchase recommendation | Ручное пополнение; `purchase.order`, `stock.quant` | Точка заказа → черновик закупки | Нет lead time/остатков; read-only API и согласование закупки | Избыточные закупки |
| Supplier quality / delay forecast | Непрозрачные поставщики; `purchase.order`, `stock.picking`, `res.partner` | Фактические сроки → оценка задержек | Не проверены даты получения и причины; API + единицы измерения | Малые выборки и неравные условия |
| Cash-flow / expense anomalies | Поздние кассовые разрывы; `account.move`, `account.payment` | Календарь платежей/выбросы → обзор | Не проверены сверка/права/доступность проводок; защищённый API | Конфиденциальность, прогноз не гарантия |
| OCR / extraction / comparison | Ручное чтение сканов; `ufs.transport.document`, `ufs.ai.document.check` | OCR и сопоставление → черновые поля | Существующий mock не читает сканы; нужны внутренний OCR, эталоны, ограниченный сервисный API и тестовые размеченные файлы | Ошибки OCR; логист проверяет оригинал |
| Incoming mail routing / draft reply | Ручная сортировка почты; `mail.message`, `res.partner` | Классификация и черновик → очередь | Нет согласованных почтовых потоков и согласий; API сообщений с ACL | Раскрытие персональных данных, никаких автоответов |
| Task extraction from messages | Задачи теряются; `mail.message`, `project.task`, `mail.activity` | Извлечение дедлайнов → черновик задачи | Нет согласованного канала и role mapping; API чтения/создания после подтверждения | Некорректный адресат/срок |
| Natural-language analytics | Медленная аналитика; `ufs.base.order`, агрегаты учёта | NL → проверенный запрос → график | Нет семантического слоя и безопасного ограничителя запросов; только утверждённые агрегирующие endpoints | Инъекции и разглашение строк |
| Fleet breakdown / fuel anomaly | Простоев и перерасход; `ufs.fleet.trip`, `ufs.fleet.refuel`, `fleet.vehicle` | Анализ пробега/топлива → предупреждение | Нет проверенного качества телеметрии и калибровки; API событий | Разные нормы по маршрутам |
| Manager quality analysis | Неясна загрузка; `ufs.base.order`, `mail.activity` | Отчёт о процессе → точки помощи | Не определены справедливые метрики и согласие сотрудников; агрегирующий API | Несправедливые выводы по отдельным сотрудникам |

Для каждого случая до live потребуются: решение по инфраструктуре и сроку хранения, список полей и ролей, контроль API/ACL, ручная проверка результата, аудит и тест на размеченных кейсах. Это идеи для discovery, не обещания реализации или ML-качества.
