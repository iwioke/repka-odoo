# Executive Brief — обзор руководителю (DEMO)

## Что это
Сводка чисел и следующих проверок из трёх аналитических сценариев.
## Какую проблему решает
Руководителю приходится сводить несколько отдельных отчётов.
## Как работает
1. Получает три отдельные синтетические выборки. 2. Запускает правила профиля клиента, экономики и пакета документов. 3. Выводит три показателя и список действий только по ненулевым отклонениям.
## Какие данные использует
`customer_data`, `margin_data`, `document_data` в `example_input.json`; в будущем Odoo-модели `res.partner`, `ufs.base.order`, `ufs.forwarder.order`, `ufs.ai.document.check`.
## Что делает AI
Никакой ML/LLM: программная агрегация объяснимых сигналов, без поиска причин изменений KPI.
## Результат
JSON с `kpis`, `actions` и предупреждением о синтетическом срезе.
## Как запустить
`python3 ai_automations/scenarios/executive_brief/run.py` (Python 3.9+, без pip); свой синтетический ввод — `--input /path/to/file.json`. `--mode live` отклоняется. Тесты: `python3 -m unittest discover -s ai_automations/.internal/tests`.
## Пример
Вход: один давний заказчик, один убыточный заказ, одна заблокированная CMR; выход: три счётчика по 1 и три задачи для проверки (`example_output.json`).
## Плюсы
Краткий единый обзор, источники показателей понятны.
## Минусы
Нет временного ряда, интерактивного dashboard и генеративного объяснения.
## Риски
Отдельные выборки могут иметь разные охваты; счётчики нельзя складывать или трактовать как реальные KPI.
## Human-in-the-loop
Руководитель проверяет исходные выборки и принимает решения самостоятельно.
## Техническая архитектура
Локальный `run.py` → `../../.internal/engine.py` (три общие функции) → JSON stdout, без сети.
## Ограничения
Только DEMO MODE; LIVE MODE требует согласованных ACL, источников и периода среза.
